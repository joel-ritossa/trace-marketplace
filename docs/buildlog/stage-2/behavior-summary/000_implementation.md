# behavior-summary — gist + step walkthrough of what the agent did

Goal: a generated description of the agent's behavior — a 1-2 sentence gist
plus a short chronological step list — on the trace-detail Analysis section
and the review resolve view, so a reviewer or prospective consumer can grasp
the run without reading the full evidence. Format (gist up front, steps
behind a collapsed disclosure) chosen by the user.

## Decisions

- **New `summary` analyzer**, modeled on `listing`: one sampled call over
  the judge rendering (judge model, no voting), fails open on malformed or
  empty output, returns None keyless. Gated by the same consent rule as the
  judge (`owner_opt_out` skips it).
- **Description, not a verdict.** The prompt forbids judging success —
  outcome is the judge's job. Prose, never a label: no confidence, no
  routing, no filter semantics, not search-visible.
- **No migration.** Unlike listing copy it is machine-owned display text,
  never owner-editable, so it lives in its `analyzer_results` row
  (`analyzer = "summary"`) and is regenerated by every delete-and-rewrite;
  `GET /v1/traces/{id}/analysis` reads it from there into a new `summary`
  field (`{gist, steps}`), additive to the response.
- Display bounds clamped in code (gist ≤ 500 chars, ≤ 10 steps × 300
  chars), mirroring `listing`'s normalization discipline.

## Plan

1. Spec: 1_analysis (Behavior Summary section), 3_api (response field),
   4_pages (both surfaces).
2. Backend: `prompts/summary.py` (V1), `analysis/summary.py`
   (`run_summary`), `SummaryResult` in models.py, registry entry, worker
   stage in `analyze_trace` under the consent gate.
3. API: `AnalysisSummary` schema + extraction in the analysis endpoint.
4. Web: shared `BehaviorSummary` component (gist + collapsed step
   disclosure); rendered in the Analysis section (after labels, before
   judge reasoning) and as a card above the machine verdict in the resolve
   view (fetched via the existing `getTraceAnalysis` call).
5. Tests: `tests/unit/test_summary.py` mirroring `test_listing.py` —
   bounds, fail-open paths, keyless, registry envelope.

## Drift

None — implemented as planned.

## Outcome

- Unit suite green (346 passed, including the 9 new summary tests); ruff
  clean; web `tsc --noEmit` clean.
- Keyless stacks and opted-out private traces produce no summary row; the
  endpoint returns `summary: null` and both surfaces omit the block.
