# Phase 05: Page Definitions

## Purpose

Define the screens around the confirmed user flows, data states, and API boundaries.

## Focus Questions

- What is the first screen a user sees?
- What pages are required for upload, ingestion status, trace library, trace detail, search, and marketplace discovery?
- What empty, loading, error, partial success, and privacy states must each page show?
- Which controls let a contributor share or list a trace?
- What information lets a consumer judge trace quality and download allowed trace data without exposing raw private content by default?

## Outputs

- Route map.
- Page responsibilities.
- Required UI states.
- Component inventory for trace inspection, upload status, search filters, result lists, and listing controls.
- Demo path through the app.

## Decision Gate

Before moving on, the page set should be small enough to build quickly and complete enough to demonstrate the full upload-to-download path.
